## 1. 为什么做

负责人反馈：网站界面“直来直去”，没有 iOS 那种丝滑感，最想要的是**页面切换动画**。

现状（生产 `feat/edgeone-hk-pilot` @ `41bc8a3`）：

- 已有一套克制的动效系统：`design/tokens.css`、`motion.ts`、`motion.css`、`components/motion/*`
- 全部用固定时长的贝塞尔曲线
- 页面切换只是新页面淡入、上移 6px（`Layout.tsx` 用 WAAPI 实现），旧页面直接消失
- 浏览器后退/前进（POP）不播动画

以下已有能力必须保留：

- 减少动态
- lite 低性能模式
- 动画不阻塞操作
- `motion.test` 对 CSS 和 JS 两边的时长做对齐检查

## 2. 目标（分三批，每批单独验收、可单独关闭）

### 第一批：导航连续感

1. **页面切换**：实现 iOS 式 push/pop。
   - 进入更深一层：新页从右侧轻推入，旧页微微左移并变淡
   - 回到上一层：动画方向反过来
   - 同层切换：只做交叉淡化
   - 页眉全程不动
2. **按压反馈**：卡片和主要按钮按下时缩到约 0.97，松手弹回。悬停上浮只在有鼠标的设备上出现（`@media (hover: hover)`）。
3. **弹簧曲线 token**：在 CSS 里用 `linear()` 写弹簧缓动，替换现有展开收起、抽屉、提示的曲线。浏览器不支持 `linear()` 时，退回现有的贝塞尔曲线。

### 第二批：共享标题和滑动指示器

4. **共享标题**：只用于下面列出的具体元素对，见 §5.4。
5. **滑动指示器**：分段按钮和标签页的选中底块，从旧位置滑到新位置。

### 第三批：手势和列表

6. **手机菜单可拖动关闭**：规则见 §5.6。
7. **列表错峰入场**：`Reveal` 的卡片列表弹簧淡入，并轻微错峰，只播一次。

## 3. 非目标

- 不做课程配图，这件事另开会话
- 不改布局、配色、文案，不加新功能
- 不改开屏动画（D-019）
- 不迁移路由：保持 `BrowserRouter`
- 不引入新的运行时依赖：不用 Motion，不用 GSAP，也不用 react-bits 组件

## 4. 反目标（出现以下任一情况，就算失败）

**操作和时长**

- 动画挡住点击、输入或阅读
- 快速连点时卡顿、排队，或者最后落到旧目标页
- 过渡动画本体超过约 400ms
- 点击后超过 300ms 还没开始跳转

**画面问题**

- 切换中闪出加载占位
- 切换中出现滚动跳动
- 白屏
- 在低端安卓或微信内置浏览器上明显掉帧

**破坏现有行为**

- 破坏减少动态、深链接、滚动恢复、`#锚点`、焦点管理
- 破坏 Ctrl/Cmd 点击、新标签页打开、外链、下载等原生链接行为

**风格**

- 劫持原生滚动，例如引入 Lenis
- 粒子、故障字、光晕等花哨效果

## 5. 已定的做法

### 5.1 技术选型

**页面切换**

- 用原生 View Transitions API（`document.startViewTransition`）。
- 不支持这个 API、调用抛错或超时时，照常跳转，并退回现有的 WAAPI 淡入。
- 一次切换只播一套动画：只要 View Transition 已经运行，就跳过旧的 WAAPI 入场动画。
- 页眉单独命名为一个过渡组，保持不动。根元素不做整页位移。

**依赖**

不增加任何运行时依赖。原因：

- Codex 指出手机菜单是首屏挂载的，`LazyMotion` 并不能自动免去首屏代价
- 拖拽一个面板、滑一个底块，用 pointer 事件和 WAAPI（FLIP）就能做

`gsap-skills` 不装。react-bits 不用；它的许可证是 MIT + Commons Clause，以后真要用，单独再提。`taste-skill` 只作为验收阶段的视觉审查参考。

### 5.2 导航协议（第一批的核心）

- **可预加载的懒加载组件**：把 `React.lazy` 换成自建包装：
  - 包装组件持有已解析的模块。模块解析完之后，再渲染它就不会挂起。
  - 预加载就是触发同一个 import，模块解析后被缓存进包装组件。

  这样过渡回调里的 `flushSync` 才能保证不触发 Suspense。只下载 chunk 不够：`React.lazy` 首次渲染必然挂起一次。

- **拦截范围**：只拦截站内 `<a>` 的普通左键点击。以下情况一律不拦截：
  - 按着修饰键点击（Ctrl、Cmd、Shift、Alt）
  - 带 `target`、`download` 的链接
  - 外链
  - 只改 hash 的链接，交给 `RouteScroll`

- **预取时机**：悬停、`touchstart`、获得焦点时开始预取。

- **竞争规则**：
  - 每次导航带一个递增编号，新的点击让旧的失效
  - 预取最多等 300ms，超时就做普通跳转，只跳一次
  - 超时或失效的预取后来才完成，不再触发跳转
  - 新导航开始前，正在播的过渡调用 `skipTransition()`
  - 在等待期间组件卸载或发生 POP，就放弃这次导航

- **截图时序**：
  1. 截旧页
  2. 在过渡回调里用 `flushSync` 提交新页
  3. 等滚动和焦点就绪（`RouteScroll` 恢复完成），最多一帧，最长约 100ms
  4. 截新页
  5. 播放过渡

  做法是让过渡回调返回一个 Promise，到第 3 步就绪时 resolve。

- **就绪等待超时**：等滚动和焦点就绪最多约 100ms。超时就跳过这次动画（`skipTransition()`），导航照常完成。
  - 新页面在 `flushSync` 时已经提交，超时后绝不能再触发第二次跳转。
  - 等待结束、超时、出错，三条路径都必须只结算一次。
- **就绪的范围**：可预加载包装只保证路由组件本身的模块已经加载好，不保证它下面的子组件不会挂起。
  - 提交新页面后，仍要检查页面是否处于加载状态：页面上有 `.page-loading`、`[data-route-pending="true"]`，或者 Suspense 正在显示加载占位。
  - 如果处于加载状态，按超时处理：跳过动画，正常显示页面。
- **浏览器后退和前进（POP）不播过渡**，保持现状。原因：
  - iPhone Safari 的边缘返回手势本身带系统动画，再叠一层会播两遍
  - POP 已有的“立即恢复滚动位置”行为保持不变

- **反向滑出**只用于页内链接导航到更浅一层的情况，例如课程页里的“返回学习页”。

- **加载失败**时（chunk 失效、网络错误）退回普通跳转，由现有的错误边界处理。

### 5.3 方向与页面身份

- 维护一张路由层级表，按层级比较决定方向：
  - 首页：0
  - 一级栏目：1
  - 课程或案例详情：2
  - 练习：3
- 比较结果：
  - 层级更深：滑入
  - 层级更浅：反向滑出
  - 层级相同或无法判断：交叉淡化
- 页面身份默认按 pathname 判断：pathname 变了就是换页。
- 只有明确列入白名单的参数变化才算同一页，不播页面过渡。初始白名单：
  - 练习题切换：`/practice/:topic/:exerciseId`
  - 技能切换：`/library/skills/:skillId`
- `/cases/:slug` 是不同案例，算换页。
- 进出全屏页 `/challenge` 时不播过渡。

### 5.4 共享标题（第二批）

只用于源和目标标题文字相同的元素对：**学习页课程卡的标题 ↔ 课程页封面的 `<h1>`**（`LessonReader` 的 `def.cover.title`）。

首页的门卡片不做共享标题：卡片标题是“从一个真实小问题开始”，和课程标题不同。门卡片只做普通的推入过渡。

规则：

- 过渡名只在点击时临时赋给被点的那张卡和目标标题，保证全页唯一，过渡结束后清除
- 以下情况降级为普通推入：
  - 目标标题没有出现
  - 导航被取消
  - 返回时源卡片不在视口里
- 实现时核对每门课卡片标题和封面标题是否完全一致，不一致的那门不做共享

### 5.5 动画策略统一

- JS 动画（View Transition、WAAPI、拖拽回弹）都从同一个函数读取当前模式：正常、lite、减少动态、后台
- CSS 的 `--motion-scale` 管不到 JS 动画，所以 JS 这边必须显式判断，不能指望 CSS 变量
- 各模式下的表现：

  | 模式 | 页面切换 | 共享元素 | 其他 |
  |---|---|---|---|
  | 减少动态 | 不用 View Transition，直接切换 | 无 | 和现有约定一致：自动动画全部关闭 |
  | lite | 只做淡化 | 无 | — |
  | 标签页在后台 | 不播 | 不播 | — |

- `linear()` 是否支持，用 `CSS.supports` 检测；WAAPI 的 easing 写在 try 里，失败就退回贝塞尔曲线

### 5.6 拖动关闭菜单（第三批）

- 右侧菜单只能沿水平方向往右拖动来关闭；往左拖有阻尼
- 纵向滚动优先：设 `touch-action: pan-y`，先判断手势方向，方向确定后再决定是否接管
- 关闭阈值：位移超过面板宽度的三分之一，或者松手时速度足够大
- 没达到阈值就弹回
- 拖动过的链接不触发点击
- 所有关闭方式走同一个关闭函数：按钮、遮罩、Escape、拖拽完成。这个函数负责：
  - 更新 `open`
  - 清理 transform
  - 恢复焦点到菜单按钮
- 减少动态时，面板仍然跟手移动（直接操作），但松手后不做回弹动画
