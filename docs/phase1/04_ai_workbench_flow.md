# 04 AI 拆题工作台 MVP 流程

## 1. 设计原则

AI 工作台第一版只做“题目理解 + 模型路线建议”，不直接做完整论文生成。

核心原则：

- 每一步都给解释，不只给结论。
- 每一步都让学生确认，避免 AI 直接替学生完成判断。
- 输出结构化，方便前端展示和后续保存。
- 禁止虚构数据、文献、比赛结果或可直接提交的终稿。

## 2. 核心流程

| 步骤 | 系统任务 | 学生任务 | 输出 |
| --- | --- | --- | --- |
| 1. 输入题目 | 接收题目文本或文件文本 | 粘贴题目、补充附件说明 | 题目原文、附件说明 |
| 2. 题型判断 | 判断物理机理、优化、评价、预测、统计分析等类型 | 确认或修改题型 | 题型标签、判断理由 |
| 3. 小问拆解 | 拆出每一问的目标、输入、输出、约束 | 检查小问是否遗漏 | 任务清单 |
| 4. 数据需求 | 列出题目数据、外部数据、可假设参数 | 确认数据来源是否能拿到 | 数据需求表 |
| 5. 模型建议 | 给基础保分模型和进阶模型 | 选择主线模型 | 模型路线表 |
| 6. 学习解释 | 解释为什么这样做、适用条件、风险 | 标记不懂的地方 | 学习提示与风险提醒 |
| 7. 下一步建议 | 给出下一步行动 | 进入对应工具或案例学习 | 行动清单 |

## 3. 人工确认点

| 确认点 | 为什么必须确认 | 页面按钮或提示 |
| --- | --- | --- |
| 题型确认 | 题型错了会导致模型方向错 | 确认题型 / 我认为不是这个类型 |
| 小问确认 | 漏掉小问会导致后续论文不完整 | 小问无遗漏 / 补充一问 |
| 数据确认 | AI 可能提出拿不到或不合规的数据 | 已有数据 / 需要外部数据 / 改用假设参数 |
| 模型确认 | 模型太复杂或不贴题会影响可解释性 | 采用基础模型 / 尝试进阶模型 / 重新推荐 |
| 进入下一步 | 确保学生理解流程，而不是直接复制 | 我已理解，进入代码 / 案例 / 论文结构 |

最低要求：第一版至少实现 4 个关键人工确认点。

## 5. Prompt 输入约束

所有工作台提示词都应包含：

- 角色：你是数学建模学习引导助手。
- 输入：只读取当前步骤需要的信息。
- 任务：只完成当前节点，不越界生成完整论文。
- 输出：使用固定表格或清单，便于网页展示。
- 质量标准：必须解释原因、列出局限、标注需要学生确认的部分。
- 禁止事项：不得虚构数据、不得承诺比赛结果、不得输出可直接提交终稿。

## 6. 风险与禁止事项

禁止：

- 直接输出最终论文正文。
- 虚构数据来源、文献、实验结果或参考资料。
- 只给模型名字，不解释适用条件。
- 绕过学生确认直接进入下一步。
- 输出“保证获奖”“直接提交”等宣传表述。

允许：

- 给论文结构建议。
- 给结果解释模板。
- 给代码骨架和函数说明。
- 给图表清单和图注建议。
- 给模型检验清单。

## 7. 示例工作台走查

输入：

> 某城市共享单车使用量随时间、天气、节假日和区域变化明显。请建立模型预测未来一周各区域需求，并提出调度建议。

预期流程：

1. 题型判断：预测 + 优化混合题。
2. 小问拆解：需求预测、区域差异分析、车辆调度建议。
3. 数据需求：历史订单、天气、节假日、区域容量、车辆库存。
4. 模型建议：时间序列或回归预测作为基础模型，整数规划或启发式调度作为进阶方案。
5. 学习解释：先预测需求，再根据缺口做调度，不直接跳到复杂优化。
6. 下一步：确认数据可获得后，进入数据清洗和特征构建。

## 8. 验收标准

- 用任意一道旧题测试，能得到清晰的小问拆解和模型路线。
- 每一步都能回答“学生需要学到什么”。
- 至少设置 4 个关键人工确认点。
- 输出内容能直接支持第二阶段前端页面开发。
