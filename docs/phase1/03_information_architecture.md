# 03 网站信息架构与页面需求

## 1. MVP 页面结构

第一版不做大而全的网站，目标是让用户一进入页面就知道：

- 这是数学建模学习平台。
- 它能一步步带我理解题目和建模流程。
- 我下一步应该进入 AI 工作台或学习路径。

MVP 核心入口：

```text
首页
├─ 学习路径
├─ AI 拆题工作台
├─ 案例库
│  └─ 案例详情页
├─ 工具箱
└─ 关于与合规说明
```

## 2. 页面清单

| 页面 | 核心作用 | 第一版内容 | 优先级 |
| --- | --- | --- | --- |
| 首页 | 建立信任和解释定位 | 口号、适用人群、核心流程、进入工作台按钮、公益说明 | P0 |
| 学习路径 | 让新手知道建模完整流程 | 读题、数据、模型、代码、图表、检验、论文的闯关卡片 | P0 |
| AI 工作台 | MVP 核心功能 | 题目输入、题型判断、小问拆解、数据需求、模型建议、人工确认 | P0 |
| 案例库 | 展示样例和教学价值 | 至少 1 个完整案例 | P0 |
| 案例详情页 | 展示从题目到论文结构的完整路径 | 背景、拆题、模型、代码框架、图表、论文结构 | P0 |
| 工具箱 | 承载后续小工具 | 数据预处理、模型选择、图表生成、模型检验、摘要优化入口 | P1 |
| 关于与合规说明 | 避免被误解为代写 | 学习用途、不生成终稿、人工确认、AI 使用记录 | P1 |

## 3. 首页内容结构

| 区块 | 内容 | 要求 |
| --- | --- | --- |
| 首屏 Hero | 项目名、定位、一句话价值、进入 AI 工作台按钮 | 不堆文字，突出“引导式学习” |
| 用户痛点 | 不会拆题、不会选模型、不会写代码、不会检验、不会写论文 | 用 5 个短卡片展示 |
| 平台流程 | 输入题目 -> AI 拆题 -> 模型建议 -> 学生确认 -> 代码/图表/论文指导 | 做成流程图或步骤条 |
| 功能入口 | 学习路径、AI 工作台、案例库、工具箱 | 每个入口一句话说明 |
| 合规边界 | 学习辅助、不生成可提交终稿、关键节点人工确认 | 必须在首页下半部分展示 |
| 协会合作 | 适合周末教学、训练营、新生培养 | 为后续合作留入口 |

首页首屏文案草稿：

标题：

> ModelingBridge / 模桥

副标题：

> 面向大学生的 AI 引导式数学建模学习平台。

说明：

> 从读题、数据、模型、代码、图表到论文表达，模桥用步骤化引导帮你理解建模流程，而不是替你完成比赛。

主按钮：

> 开始 AI 拆题

次按钮：

> 查看学习路径

## 4. 学习路径页

采用闯关式模块，但第一版先做结构和样例，不做大型课程系统。

| 模块 | 学习目标 | 输入材料 | AI 能帮什么 | 学生必须确认什么 | 合格标准 |
| --- | --- | --- | --- | --- | --- |
| 读题拆解 | 理解题目、小问和目标 | 题目文本、附件说明 | 拆分小问、提取目标和约束 | 是否漏问、题意是否理解正确 | 能说清每问输出 |
| 数据理解 | 明确需要什么数据 | 题目数据、附件字段 | 列数据字段、来源和替代方案 | 数据是否真实可获得 | 能写出数据需求表 |
| 模型选择 | 选择基础模型和进阶模型 | 小问分析、数据需求 | 推荐模型、解释适用条件 | 主线模型是否合理 | 能解释选型原因 |
| 代码实现 | 把模型转成程序结构 | 模型方案、数据字段 | 给文件结构、函数和伪代码 | 是否能本地运行和修改 | 能开始写代码 |
| 图表表达 | 规划结果展示 | 模型输出、指标 | 建议图表和图注 | 图表是否支撑结论 | 图表能服务论文 |
| 模型检验 | 检查结果可靠性 | 结果数据、模型参数 | 给检验方法和风险提示 | 检验是否符合题目 | 能说明结果可信度 |
| 论文写作 | 组织表达结构 | 分析过程、结果图表 | 给章节大纲和写作要点 | 是否由学生自己完成表达 | 能形成论文提纲 |

## 5. AI 工作台页面

第一版页面结构：

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 题目输入区 | 粘贴题目文本，填写附件说明 | 点击“开始分析” |
| 进度步骤条 | 题型判断、小问拆解、数据需求、模型建议、学习解释、下一步 | 显示当前步骤 |
| 步骤卡片区 | 每一步的结构化输出 | 展开、折叠、复制 |
| 人工确认区 | 题型、小问、数据、模型、进入下一步 | 确认或要求重新分析 |
| 输出汇总区 | 任务清单、模型路线、行动清单 | 保存为项目记录 |

第一版不做：

- 登录系统
- 多人协作编辑
- 自动在线运行代码
- 直接生成完整论文

## 6. 案例库与案例详情页

案例库列表字段：

| 字段 | 示例 |
| --- | --- |
| 标题 | 校园共享单车需求预测与调度建议 |
| 难度 | 入门 / 中等 / 进阶 |
| 覆盖环节 | 读题、数据、模型、代码、图表、论文 |
| 适合对象 | 第一次参加建模训练的同学 |
| 数据状态 | 题目附件 / 公开数据 / 需人工确认 |

案例详情页结构：

1. 案例背景
2. 学习目标
3. 题目拆解
4. 数据需求
5. 模型路线
6. 代码框架
7. 图表计划
8. 检验清单
9. 论文结构
10. 学生需要自己完成的部分

## 7. 工具箱页

第一版做入口，不追求全部工具可用。

| 工具 | 第一版状态 | 说明 |
| --- | --- | --- |
| 数据预处理助手 | 入口说明 | 字段、缺失值、单位、异常值检查 |
| 模型选择助手 | 可与 AI 工作台复用 | 根据题型和数据推荐模型 |
| 图表建议助手 | 入口说明 | 给图表类型、图注和论文位置 |
| 模型检验清单 | 静态模板 | 稳定性、敏感性、误差、合理性 |
| 论文结构助手 | 入口说明 | 只给结构和写作要点 |

## 8. 页面验收标准

- 用户 30 秒内能看懂网站是做什么的。
- 首页有明确按钮进入 AI 工作台。
- 每个页面都有清晰目标，不重复、不空泛。
- 页面文案坚持学习辅助定位。
- 首页、学习路径、AI 工作台、案例库至少有低保真需求说明。
