# 07 第一阶段验收与第二阶段交接

## 1. 验收目标

第一阶段完成的标志不是“写了很多想法”，而是能拿出六类证据：

- 定位清楚
- 调研真实
- 页面明确
- AI 流程可演示
- 内容可落地
- 技术可开工

如果调研不足、AI 流程不清或页面原型未定，不建议进入第二阶段开发。

## 2. 验收材料清单

| 类别 | 必须材料 | 当前状态 | 通过标准 |
| --- | --- | --- | --- |
| 定位材料 | 项目定位一句话、目标用户、合规边界清单 | 已有文档模板 | 团队能统一口径说明 |
| 调研材料 | 10-20 份访谈记录、痛点分类表、功能优先级表 | 待执行调研 | 至少 10 份真实反馈 |
| 网站材料 | 信息架构图、首页原型、AI 工作台原型、学习路径页原型 | 已有需求文档 | 能指导前端设计 |
| AI 流程材料 | 工作台流程图、人工确认点、输出格式模板 | 已有流程文档 | 能用旧题走通 |
| 内容材料 | Prompt Library v0.1、一个案例样例包 | 已有 v0.1 草稿 | 能支持 Demo 展示 |
| 技术材料 | 仓库、目录结构、技术栈说明、接口草案 | 已有技术文档 | 第二阶段可开工 |
| 试点准备 | 至少 5 名种子用户或协会试点沟通记录 | 待调研补齐 | 有明确试用对象 |

## 3. 验收会议流程

| 环节 | 内容 | 建议时长 |
| --- | --- | --- |
| 项目定位复述 | 每个成员用 1 分钟说明项目是什么、不是什么 | 5 分钟 |
| 调研结论汇报 | 展示用户痛点 Top 5 和功能优先级 | 10 分钟 |
| 网站原型走查 | 从首页进入 AI 工作台，走一遍用户路径 | 15 分钟 |
| AI 流程测试 | 拿一道旧题输入，检查拆题和模型建议是否可用 | 20 分钟 |
| 技术准备检查 | 检查目录结构、接口草案、提示词文件、案例文件 | 10 分钟 |
| 进入第二阶段决策 | 决定做什么、砍什么、谁负责、什么时候交付 | 15 分钟 |

## 4. 进入第二阶段的条件

必须满足：

- 项目边界清楚：所有成员都知道不做替代性参赛、不承诺比赛结果、不输出可直接提交终稿。
- 有真实需求证据：至少 10 份访谈或问卷记录。
- 网站页面明确：至少完成首页、学习路径、AI 工作台、案例库的低保真需求说明。
- 核心流程可演示：不用正式网页，也能用文字和样例走完整个 AI 拆题流程。
- 内容可落地：至少有一个案例和一套提示词能支持 Demo。
- 技术可开工：目录、接口草案、开发环境和风险清单已经准备好。

## 5. 第二阶段 MVP Backlog

| 优先级 | 任务 | 建议负责人 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 开发首页静态页面 | 前端负责人 | 首页可访问，含 Hero、流程、入口、边界说明 |
| P0 | 开发 AI 工作台前端页面 | 前端负责人 | 能输入题目并展示步骤卡片 |
| P0 | 开发题目分析接口 | 后端负责人 | 输入题目文本后返回结构化 JSON |
| P0 | 接入读题拆解 Prompt | AI / 算法负责人 | 旧题测试输出稳定 |
| P0 | 录入一个完整案例 | 内容负责人 | 案例详情页可展示完整路径 |
| P1 | 保存用户反馈 | 后端负责人 | 可保存使用反馈和问题标记 |
| P1 | 工具箱静态入口 | 前端负责人 | 展示入口和功能说明 |
| P1 | Prompt 版本管理 | AI / 内容负责人 | 能查看当前 Prompt 版本和更新时间 |
| P2 | 简单项目记录 | 后端负责人 | 用户可保存一次分析结果 |
| P2 | 部署演示环境 | 工程负责人 | 团队外用户可访问 Demo |

## 6. 风险问题与待决策事项

| 问题 | 当前建议 | 需要何时决定 |
| --- | --- | --- |
| 项目正式名称 | 暂用 ModelingBridge / 模桥 | 第二阶段首页设计前 |
| 第一版模型供应商 | 采用 OpenAI 兼容封装，不绑定供应商 | 后端开发前 |
| 案例最终题目 | 暂用共享单车教学案例 | 案例页开发前 |
| 是否需要登录 | 第一版不做登录 | 用户反馈保存前 |
| 是否进入协会试点 | 先收集 5 名种子用户 | 调研完成后 |
