# 03 AI 使用记录与合规说明

> 适用于：ModelingBridge / 模桥 · 免费试运行期  
> 适用对象：使用本平台的学生、协会教学组、指导老师

---

## 1. 为什么需要 AI 使用记录

### 核心原因（三条）

**1）学习闭环需要记录**  
AI 的引导过程是学生建模思维形成的一部分。如果只有 AI 的输出，没有记录哪些内容被学生确认、哪些被修改，事后无法复盘学生真正学到了什么。

**2）合规和透明需要记录**  
国内外建模竞赛对 AI 工具使用的规范正在收紧。学生如果在赛后无法说清楚哪些内容是 AI 辅助、哪些是自己完成的，容易在争议时处于被动。记录的存在本身就是透明的证据。

**3）平台改进需要记录**  
提示词版本、AI 输出质量、哪些步骤用户最常修改——这些信息只有通过记录才能被统计，才能指导下一版优化方向。

### 记录不是监控

> 记录的目的是帮助学生理解自己做了什么、帮平台改进质量、帮老师了解辅助程度。  
> 记录不用于评分、不用于举报，也不对外公开具体内容。

## 2. 工作台每一步应该记录什么

> 以下是推荐的记录字段，未来工作台实现"保存为项目记录"功能时按此结构存储。  
> 当前阶段（本地演示版），学生可以手动复制输出并在本地文档中记录。

### 2.1 记录结构总览

| 记录层级 | 内容 | 存储形式 |
|----------|------|----------|
| 会话元信息 | 使用时间、提示词版本、题目标题 | 自动记录 |
| 每步输入 | 学生输入的题目文本、附件说明 | 自动记录 |
| 每步 AI 输出 | AI 返回的结构化结果摘要 | 自动记录 |
| 人工确认节点 | 学生点击"确认"或"修改"的时间和内容 | 自动记录 |
| 学生修改内容 | 学生对 AI 输出的修改或补充 | 人工填写 / 自动捕获 |
| 反馈标记 | 学生标记"这里不准确"的具体步骤 | 人工填写 |

### 2.2 每一步的具体记录字段

#### 步骤 1：输入题目

| 字段 | 说明 | 示例 |
|------|------|------|
| 题目原文 | 粘贴的完整题目文本 | "某高校共享单车在高峰时段..." |
| 附件说明 | 学生填写的附件描述 | "提供了CSV格式历史订单数据，含日期、区域、数量字段" |
| 输入时间 | 系统自动记录 | 2026-05-10 14:23 |
| 提示词版本 | 当前使用的 prompt 版本号 | v0.3-analyze |

#### 步骤 2：题型判断

| 字段 | 说明 |
|------|------|
| AI 判断的题型 | 例如：预测 + 优化混合题 |
| AI 判断依据 | AI 给出的理由摘要（100 字以内） |
| 学生确认结果 | 接受 / 修改为其他类型 |
| 学生备注 | 如果学生修改，写明原因 |

#### 步骤 3：小问拆解

| 字段 | 说明 |
|------|------|
| AI 拆解的小问列表 | 每一问的目标、输入、输出、约束 |
| 学生确认结果 | 无遗漏 / 补充了第 X 问 |
| 补充内容 | 学生新增或修改的小问描述 |

#### 步骤 4：数据需求

| 字段 | 说明 |
|------|------|
| AI 建议的数据字段列表 | 字段名、来源建议、必须/可选 |
| 学生确认的数据可获得性 | 每个字段：已有 / 需要外部 / 改用假设 |
| 学生补充的字段 | 题目中有但 AI 遗漏的数据 |
| 人工确认标记 | 外部数据来源是否已人工核实 |

#### 步骤 5：模型建议

| 字段 | 说明 |
|------|------|
| AI 推荐的基础模型 | 模型名称、适用原因摘要 |
| AI 推荐的进阶模型 | 模型名称、适用原因摘要 |
| 学生选择的主线模型 | 学生最终选择哪个，以及原因 |
| 学生对推荐的评价 | 合理 / 有疑问（写明哪里） / 不采用（写明原因） |

#### 步骤 6：代码框架

| 字段 | 说明 |
|------|------|
| AI 给出的文件结构和函数骨架 | 以代码块形式存储 |
| 学生修改的部分 | 哪些函数被改动，改成了什么逻辑 |
| 本地运行结果 | 学生是否成功在本地运行（是 / 否 / 待运行） |

#### 步骤 7：图表计划

| 字段 | 说明 |
|------|------|
| AI 推荐的图表清单 | 图表名称、对应小问、展示目的 |
| 学生确认采用的图表 | 最终决定画哪些图 |
| 实际生成结果 | 每张图的实际生成状态（已生成 / 待生成） |

#### 步骤 8：检验与论文（如已实现）

| 字段 | 说明 |
|------|------|
| AI 给出的检验方法清单 | 方法名称、针对哪一问 |
| 学生完成的检验 | 哪些已完成、哪些未做（写明原因） |
| 论文章节框架 | AI 给出的框架（只含结构，不含正文） |
| 学生实际撰写的内容 | 每章由学生完成的字数范围（大致即可） |

## 3. 用户对外披露时可参考的说明模板

> 以下模板供学生在需要声明 AI 使用情况时参考（例如：课程作业说明、竞赛申报说明、论文附录）。  
> 请根据实际情况修改，不要直接照搬不适用的部分。

### 模板 A：简短声明版（适合附在论文末尾或提交材料中）

> 本作品在完成过程中使用了 ModelingBridge（模桥）AI 学习辅助工具进行题目拆解和模型路线引导。具体使用环节包括：读题拆小问、数据需求梳理、模型选型建议。AI 工具的输出经本人（团队）逐步人工审核和修改确认，最终模型选择、数据处理、代码实现、图表绘制及论文撰写均由本人（团队）独立完成。

### 模板 B：详细说明版（适合需要说明使用过程的场合）

> 在本次建模过程中，我们使用 ModelingBridge（模桥）作为 AI 辅助学习工具。该工具的功能定位为"引导式建模学习助手"，而非论文生成工具。
>
> 具体使用方式如下：
> - 题目拆解环节：使用工作台的"读题拆解"功能，AI 给出了初步的题型判断和小问拆解，经我们确认后作为研究框架的起点。
> - 数据需求环节：使用工作台的"数据需求"功能，AI 列出了可能需要的数据字段和来源建议，实际数据由我们通过题目附件和公开数据源获取，并经人工核实。
> - 模型建议环节：使用工作台的"模型推荐"功能，AI 给出了基础模型和进阶模型的建议及适用原因，最终模型选择由我们根据题意和数据条件自行判断。
>
> 本文中所有数据、公式推导、模型参数设置、代码实现、图表绘制和文字表达均由团队成员独立完成，AI 工具未参与最终论文正文的撰写。

### 模板 C：给指导老师的一句话说明

> 我在建模过程中用了一个 AI 辅助工具帮我理解题目和选模型，但数据、代码和论文是我自己写的，工具没有直接输出可以提交的内容。

## 4. 明确边界：AI 在平台中的定位

### AI 可以做的（明确允许）

| 允许的事项 | 具体体现 |
|------------|----------|
| 拆解题目结构 | 识别题型、拆分小问、提取输入输出约束 |
| 解释建模概念 | 解释为什么选某个模型、模型的适用条件和局限 |
| 给出路线建议 | 基础模型和进阶模型的选型建议，但需学生确认 |
| 提供代码骨架 | 文件结构、函数划分、伪代码，不含完整实现 |
| 规划图表和论文结构 | 推荐图表清单、章节大纲，不写正文 |
| 提示检验清单 | 列出需要做的检验方法，不替学生执行检验 |

### AI 不能做的（明确禁止）

| 禁止的事项 | 原因 |
|------------|------|
| 生成可直接提交的论文正文 | 不符合学习辅助定位，有学术规范风险 |
| 虚构数据、文献或实验结果 | 破坏数据来源可靠性 |
| 替学生完成最终的模型判断 | 学生必须理解为什么这样选 |
| 承诺比赛结果或奖项 | 比赛结果无法控制 |
| 跳过人工确认节点直接推进 | 违背引导式学习原则 |
| 自动从网络搜索数据 | 来源可靠性难以核验 |

### 学生必须自己完成的（核心任务）

> 以下内容无论 AI 有多强，都不能替代学生完成：

1. **真实数据的获取与合规确认**：数据来源是否合法，字段是否与题目要求对应，这需要学生自己判断。
2. **模型参数的取值依据**：参数为什么是这个值，需要学生能解释。
3. **代码的实际实现**：骨架只是起点，代码能不能跑、结果是否正确，是学生自己的工作。
4. **论文的措辞和原创表达**：章节框架 ≠ 论文正文，文字表达是学生自己的思维输出。
5. **对结果的主观判断和讨论**：结果说明什么、有什么局限、能不能推广，这些判断必须来自学生。

## 5. 面向老师/协会的说明话术

> 以下话术适合在向指导老师或协会负责人介绍平台时使用。

### 5.1 一句话说明

> 模桥是一个 AI 学习引导工具，它帮学生把题目读懂、把模型选对，但不替学生写论文、不承诺比赛结果。关键步骤都要学生自己确认，AI 的使用过程也有记录可查。

### 5.2 给担心 AI 替学生完成作业的老师

> 我们理解这个顾虑。模桥的设计逻辑是"AI 只做引导，学生做决定"。具体来说：
>
> - 工作台每一步都有人工确认节点，AI 给建议，学生选择是否采纳。
> - AI 不生成可直接提交的论文正文，只给章节框架和写作要点。
> - 学生使用过程有记录，可以事后查看哪些步骤是 AI 辅助、哪些是学生完成。
> - 数据获取、代码实现、图表绘制和文字撰写，都是学生自己来的工作。
>
> 我们的目标是让新手不再"因为不知道从哪里开始"就放弃，而不是帮他们绕过学习过程。

### 5.3 给协会周末课教学组

> 模桥可以作为周末课的辅助工具，但不是课程本身的替代。我们建议的使用方式是：
>
> - 讲师用案例库作为教学样例，展示"从题目到论文结构"的完整逻辑。
> - 新生在练习环节用工作台走一遍真实题目，感受每一步在做什么。
> - 讲师在关键步骤（尤其是模型选择）停下来讲解，工作台的输出作为讨论起点。
>
> 工具降低了新生的起步难度，但讲师的解释和引导仍然是周末课的核心价值。

### 5.4 给担心 AI 数据不可靠的老师

> 平台在所有涉及外部数据的地方，都标注了"需人工确认"。AI 不会自动引用它不确定的数据来源，也不会编造数字。如果学生使用了外部数据，需要自己找到原始来源并确认其可信度，这一步是不能省的。
