# 07 工具箱检查清单

> 适用于：完成建模后提交前的自查 / 协会课程"检查环节"教学材料  
> 使用方式：逐项勾选，未勾选的项目必须有说明或补做  
> 共 6 个维度，42 个检查项

---

## 使用说明

这份清单的设计逻辑：**每一项都是"没做会失分"或"没做会出错"的内容**，不是可选项。

每一项的格式：
- **做了什么**：具体操作是什么
- **为什么做**：不做的风险是什么
- **合格标准**：怎么判断自己做了

---

## 维度一：数据处理

### D-01 数据来源记录
- **做了什么**：为每类数据写明来源（题目附件 / 公开数据集 + 链接 / 人工整理 / 合理假设）
- **为什么做**：没有来源的数据在论文中等于"凭空捏造"，评委会质疑可信度；竞赛越来越强调数据合规
- **合格标准**：论文中"数据说明"节能为每个数据字段写出具体来源，外部数据能提供访问链接或引用格式
- ☐ 已完成

### D-02 缺失值处理
- **做了什么**：检查所有字段是否有缺失，选择合适的处理方式（删除行 / 均值填充 / 插值），并记录
- **为什么做**：缺失值不处理，模型训练会报错或产生偏差；不同填充方式对结果影响不同
- **合格标准**：代码中有明确的缺失值处理步骤；论文中注明"共发现 X 个缺失值，采用 XX 方式处理"
- ☐ 已完成

### D-03 异常值检测
- **做了什么**：用箱线图或 3σ 原则识别异常值，决定是删除、修正还是保留并说明
- **为什么做**：一个极端异常值可能让整个模型的参数估计偏离；不处理异常值是低级失误
- **合格标准**：画过箱线图或计算过四分位距；论文中说明是否发现异常值以及如何处理
- ☐ 已完成

### D-04 量纲统一
- **做了什么**：检查不同字段的单位是否一致（如时间统一为小时、金额统一为万元）
- **为什么做**：量纲不同的变量混合计算（如米和千米同时出现），会导致模型结果错误
- **合格标准**：所有参与计算的变量在"符号说明"中都注明了单位；同类变量统一了单位
- ☐ 已完成

### D-05 训练/测试集划分
- **做了什么**：将数据划分为训练集和测试集，时序数据按时间顺序划分（不能随机）
- **为什么做**：用全量数据训练再测试，测试误差虚低，没有泛化意义；随机划分时序数据会导致数据泄露
- **合格标准**：测试集是模型训练时从未见过的数据；时序数据的测试集是时间上靠后的数据
- ☐ 已完成

### D-06 特征工程记录
- **做了什么**（适用于有特征的预测模型）：记录每个特征的构造方式（如"lag_1h = 前 1 小时订单量"）
- **为什么做**：滞后特征如果构造错误会导致数据泄露；特征说明不清楚评委看不懂模型
- **合格标准**：论文中有特征列表，每个特征说明含义和构造方式
- ☐ 已完成 / ☐ 不适用（模型无特征工程）

## 维度二：模型建立

### M-01 模型选择依据
- **做了什么**：说明为什么选这个模型，而不是其他模型；从题型、数据类型、模型假设三个角度解释
- **为什么做**：只列模型名字不解释选型理由，评委认为你不理解模型，只是随便用的
- **合格标准**：论文中有"模型选择依据"段落，至少提到"适用条件"和"相比于其他模型的优势"
- ☐ 已完成

### M-02 假设列表
- **做了什么**：把所有隐含假设都显式列出来（例如"假设运输成本与距离成正比"）
- **为什么做**：没有假设的模型是不诚实的；隐含假设暴露了你的模型局限
- **合格标准**：论文第一章有"基本假设"表格，每条假设写明依据；数量通常 3—8 条
- ☐ 已完成

### M-03 模型公式完整性
- **做了什么**：确认所有决策变量、目标函数、约束条件都用数学符号完整写出
- **为什么做**：只用文字描述模型而无公式，论文学术性不够；评委无法验证模型是否正确
- **合格标准**：目标函数有明确的数学表达式；约束条件逐条写出（不能只说"还有其他约束"）
- ☐ 已完成

### M-04 参数取值依据
- **做了什么**：对模型中所有参数（超参数、权重系数等），说明为什么是这个值（数据拟合 / 文献参考 / 题目给出 / 敏感性分析确定）
- **为什么做**：参数取值无依据是高频失分点；评委问"这个参数怎么定的"，你要能回答
- **合格标准**：论文中有"参数说明"节；每个参数后面有来源注释
- ☐ 已完成

### M-05 基准模型（Baseline）对比
- **做了什么**：建立一个最简单的基准解（如预测取历史均值、调度不做优化），与你的模型结果对比
- **为什么做**：没有对比，"模型效果好"是相对于什么好？评委无法评估你的改进幅度
- **合格标准**：论文中有 Baseline 的定义和结果；你的模型相比 Baseline 的提升量是多少（定量）
- ☐ 已完成 / ☐ 不适用（评价类模型无 Baseline）

## 维度三：代码实现

### C-01 代码能在本地运行
- **做了什么**：在干净的 Python 环境中从头运行一遍，确认不报错
- **为什么做**：代码报错说明实现有问题；评委若要复现结果，跑不通会严重影响信任
- **合格标准**：从 `main.py`（或入口脚本）运行一遍，无报错，输出结果与论文一致
- ☐ 已完成

### C-02 输出结果与论文一致
- **做了什么**：检查代码输出的数字和图表，是否与论文中展示的完全一致
- **为什么做**：代码改动后忘记更新论文，或论文里数字手动输入有误，会造成结论前后矛盾
- **合格标准**：论文中的关键数字（MAE、总成本、排名等）与代码最终输出一一对应
- ☐ 已完成

### C-03 代码有必要注释
- **做了什么**：在关键步骤（数据清洗方式、约束条件定义、特征含义）写注释
- **为什么做**：比赛后复盘或请人帮看代码时，没有注释看不懂
- **合格标准**：每个核心函数有一行说明其输入输出；复杂的数学运算旁边有公式注释
- ☐ 已完成

### C-04 随机种子固定
- **做了什么**（适用于有随机性的模型）：在代码开头设置 `random.seed(42)`, `np.random.seed(42)` 等
- **为什么做**：树模型、神经网络等有随机初始化，不固定种子每次运行结果不同，无法复现
- **合格标准**：所有使用随机数的库都设置了固定种子；论文中注明"已设置随机种子确保结果可复现"
- ☐ 已完成 / ☐ 不适用（模型无随机性）

## 维度四：图表

### V-01 每张图有明确目的
- **做了什么**：为每张图写一句话说明"这张图支撑哪一问的哪个结论"
- **为什么做**：图表只是展示，没有对应文字分析，评委不知道图说明了什么；"为画图而画图"是大忌
- **合格标准**：论文中每张图前后都有段落引用该图并解释结论
- ☐ 已完成

### V-02 图表标签完整
- **做了什么**：检查每张图：坐标轴标签（含单位）、图例、标题、图注（图 X）是否完整
- **为什么做**：缺少坐标轴单位或图例，评委读不懂图；这是最常见的低级扣分点
- **合格标准**：用以下清单检查每张图：☐ 标题 ☐ x 轴标签+单位 ☐ y 轴标签+单位 ☐ 图例（多条线时）☐ 图注（图 X）
- ☐ 已完成

### V-03 图表数量合理
- **做了什么**：检查图表数量是否适当，通常 4—8 张为宜，不是越多越好
- **为什么做**：图太多显得没有重点；每张图都必须在论文中被引用和解释，否则宁可删掉
- **合格标准**：每张图在论文正文中都被显式提到；删掉任何一张图，论文的某个结论就缺少支撑
- ☐ 已完成

### V-04 图表分辨率和可读性
- **做了什么**：导出图片分辨率 ≥ 300 DPI；字体大小在缩小后仍可阅读
- **为什么做**：低分辨率图片打印出来模糊；字体太小评委看不清标签
- **合格标准**：在 Word 或 PDF 中把图缩小到论文实际大小后，所有文字仍然清晰
- ☐ 已完成

## 维度五：模型检验

### T-01 误差指标计算（预测类）
- **做了什么**：计算并报告 MAE（平均绝对误差）、RMSE（均方根误差），可选 MAPE
- **为什么做**：只说"模型效果好"不定量，无法判断模型是否真的可用；与 Baseline 对比才有意义
- **合格标准**：测试集上的误差指标在论文中以表格形式展示；说明了这个误差在实际应用中意味着什么
- ☐ 已完成 / ☐ 不适用

### T-02 约束满足验证（优化类）
- **做了什么**：代码验证所有约束条件都被满足（如需求量是否全部得到满足、库存是否未超出）
- **为什么做**：求解器返回"最优解"不代表约束真的满足，数值精度问题可能导致微小违反
- **合格标准**：代码中有断言（assert）或打印验证；论文中写"验证了所有约束条件均满足"
- ☐ 已完成 / ☐ 不适用

### T-03 灵敏度分析
- **做了什么**：对关键参数（成本系数、权重、预测误差等）做 ±X% 的扰动，观察结论是否改变
- **为什么做**：参数估计本身有不确定性，若结论对参数极度敏感，结论的可信度就低
- **合格标准**：论文中有"灵敏度分析"节；扰动范围有依据；分析结论是定量的（"当参数变化超过 X% 时，结果改变"）
- ☐ 已完成

### T-04 稳健性检查（评价类）
- **做了什么**：对权重向量做随机扰动，统计排名变化频率
- **为什么做**：熵权法给出的权重本身有不确定性，排名若对权重非常敏感，结论可信度低
- **合格标准**：进行了 ≥100 次权重扰动；统计了排名变化频率；结论说明了哪些排名稳定、哪些不稳定
- ☐ 已完成 / ☐ 不适用

### T-05 残差分析（回归类）
- **做了什么**：画残差图（残差 vs 预测值），检查残差是否随机分布；做 Shapiro-Wilk 或 QQ 图检验正态性
- **为什么做**：残差有规律说明模型设定有问题（如漏掉了某个重要特征）；正态性假设不满足时，p 值不可信
- **合格标准**：残差图在论文中展示；论文中有对残差分布的说明
- ☐ 已完成 / ☐ 不适用

### T-06 交叉验证（预测类）
- **做了什么**：用交叉验证（时序数据用 TimeSeriesSplit）评估模型泛化能力
- **为什么做**：单次划分的测试误差受划分方式影响大；交叉验证给出更稳健的误差估计
- **合格标准**：报告了 CV 均值和标准差；说明了 CV 的折数和方式
- ☐ 已完成 / ☐ 不适用

## 维度六：论文结构

### W-01 摘要格式检查
- **做了什么**：检查摘要是否包含：问题背景、使用方法、主要结论（定量）、建议
- **为什么做**：评委首先读摘要，摘要没有定量结论，印象大打折扣
- **合格标准**：摘要中至少出现 2—3 个定量数字（如误差值、成本降低比例、排名结论）
- ☐ 已完成

### W-02 符号说明完整性
- **做了什么**：检查论文中所有数学符号是否都在"符号说明"节中定义
- **为什么做**：符号未定义直接使用，评委看不懂，也容易出现符号不一致的低级错误
- **合格标准**：能在"符号说明"表中找到论文每一处数学符号的定义
- ☐ 已完成

### W-03 图表在正文中被引用
- **做了什么**：确认每张图在正文中有"如图 X 所示"或"见图 X"的引用
- **为什么做**：图不被引用说明它是多余的；论文中图和正文脱节是常见问题
- **合格标准**：检索论文中所有"图 X"，确认每个编号都在正文中至少出现一次
- ☐ 已完成

### W-04 结论定量表达
- **做了什么**：检查所有结论是否有具体数字，避免只说"效果更好"、"明显改善"
- **为什么做**：定性结论没有说服力；比赛结论必须定量才能让评委信服
- **合格标准**：每个关键结论后面都有对应的数字支撑（例如"缺车率从 X% 降至 Y%"）
- ☐ 已完成

### W-05 参考文献格式
- **做了什么**：检查参考文献是否格式统一（期刊 / 书籍 / 网站格式规范），且只列真实查阅过的文献
- **为什么做**：虚假引用是学术不端；格式不统一影响专业印象
- **合格标准**：每条引用在正文中都有对应的 [数字] 标注；网站引用注明了访问日期
- ☐ 已完成

### W-06 模型局限与改进方向
- **做了什么**：在论文评价节主动列出至少 2 个模型的局限，并给出对应的改进方向
- **为什么做**：主动指出局限比被评委发现局限要好得多；这展示了批判性思维
- **合格标准**：每个局限写明"什么假设导致了什么局限，如何可以改进"
- ☐ 已完成

## 快速检查清单（5 分钟版）

> 比赛提交前最后 5 分钟扫一遍：

```
数据层面：
□ 每个数据字段都有来源
□ 训练/测试集没有用未来数据

模型层面：
□ 约束条件写全了（不只是目标函数）
□ 所有参数有取值依据

图表层面：
□ 每张图有坐标轴标签和单位
□ 每张图在正文里被引用

检验层面：
□ 做了某种形式的灵敏度或稳健性分析
□ 结论有定量数字，不只是定性描述

论文层面：
□ 摘要里有数字
□ 假设表格存在
```
