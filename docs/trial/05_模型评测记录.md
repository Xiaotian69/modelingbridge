# 05 模型评测记录

> 记录目的：比较 DeepSeek 与 Xiaomi MiMo 在“AI 引导式建模学习工作台”中的题型判断、模型建议、数据清单和学习引导质量。本文只记录评测结论，不记录任何 API Key。

## 1. 本轮评测范围

- 评测时间：2026-05-24
- 调用接口：`POST /api/analyze-problem`
- 学生水平：`beginner`
- 模型范围：DeepSeek、Xiaomi MiMo
- 题目数量：3 道轻量样题
- 评测目标：先确认双模型可用性与输出风格差异，后续再扩展到 5 道以上正式评测题集。

## 3. 初步结论

DeepSeek 的题型命名更贴近数学建模竞赛表达，能较快把“预测 + 调度”“评价 + 排名”这类混合任务拆出来。模型候选覆盖面较广，适合默认作为试运行主力模型。

MiMo 的输出也能稳定返回结构化结果，没有触发演示回退。它的模型建议偏保守、教学语气更直白，适合放在工作台里作为对比测试模型；但在正式推荐前，还需要用更多题目观察它对混合题主次关系、复杂约束和检验方案的把握。

两者本轮都能生成可用的数据清单与小问拆解。现阶段更适合把双模型能力定位为“试运行中的质量对比”，不要在页面文案里宣传“多模型保证正确”。

## 4. 后续评测动作

1. 由 ClaudeCode 补齐至少 5 道评测题，覆盖预测、优化、评价、机理、混合题。
2. Codex 用同一批题跑双模型，补充“题型是否准确、模型是否过泛、数据项是否可执行、人工确认点是否清楚”四列评分。
3. 对明显偏泛的输出，优先优化提示词中的“教学样例要求”和“不要直接给论文答案”约束。
4. MiMo 在 5 道题以上表现稳定后，再考虑调整默认模型策略；当前仍建议 DeepSeek 作为默认入口，MiMo 作为测试/对照入口。
