# iOS 式动效 · 第一批 验收报告

日期：2026-10-20
分支：`feat/motion-ios-20261020`（基于生产 `41bc8a3`，**未推送**）
设计：`docs/superpowers/specs/2026-10-20-ios-motion-design.md`
计划：`docs/superpowers/plans/2026-10-20-motion-batch1.md`

## 做了什么

- **页面切换**：用浏览器原生 View Transitions 实现，不新增依赖，路由也没改。
  - 进入更深一层：新页从右侧推入，旧页微微左移、淡出。
  - 返回上一层：方向相反。
  - 同层页面之间：交叉淡化，0.2 秒。
  - 页眉不动。
  - 推入和返回动画 0.34 秒，用弹簧曲线。
- **不播过渡的情况**：
  - 浏览器后退和前进，避免和 iPhone 系统的返回手势叠加；
  - 同一页内的锚点跳转；
  - 换练习题、换技能；
  - 进出 `/challenge`；
  - 系统开启“减少动态”时。
- **低性能设备**（lite 模式）：只做淡化。
- **跳转规则**：
  - 连续点击时，最后一次点击生效。
  - 预加载最多等 0.3 秒，超时就直接打开新页，不放动画。
  - 每次点击最多跳转一次。
  - 新页在 0.1 秒内没准备好，或者还在加载：照常跳转，只是不放动画。
- **按压反馈**：按钮和卡片按下时缩到 0.97，松手时带一点回弹。悬停上浮只在有鼠标的设备上出现。
- **弹簧曲线**：展开收起、抽屉打开改用弹簧曲线。浏览器不支持 `linear()` 时，退回原来的曲线。

## 浏览器实测中发现并修好的两个问题

1. **所有过渡都被跳过**：浏览器在过渡回调执行期间会暂停渲染帧，而原来的滚动恢复要等下一帧才执行，于是每次都等到 0.1 秒超时。改为提交新页面后立即执行滚动恢复。
2. **平滑滚动还没停时点链接，新页停在半中间**：没播完的平滑滚动会在过渡结束后接着播。改为截取旧页快照之前，先把滚动停在当前位置。

两处修复都先写了能复现问题的测试，修复后测试通过。

## 独立审查后修复的问题

审查结论：没有严重问题，有 2 个重要问题，已全部修复。

1. **顶部导航“刷题”**：它指向 `/practice`，这是一个重定向。原来的过渡截到的是重定向前的空白页，首次访问时还会闪出加载占位。现在跳转时直接把目标解析为 `/practice/linear-programming`，历史记录和生产版完全一样。实测：不闪加载占位，后退直接回到学习页。
2. **补上预取**：鼠标悬停、手指触摸、获得焦点时，就开始预取目标页的代码（设计 §5.2）。实测：悬停在“刷题”上，练习页代码即被取回，点击后 0.03 秒开始动画。
3. **页面自己改网址时，用户的点击不再被丢掉**：原来等待预取期间，只要当前页面用 replace 改了网址（比如筛选条件），这次点击就会被作废。现在只有当用户真的离开了当前页面（例如按了后退），才作废这次点击。

以下小问题记入待办，留到下一批处理：
- 在动画播放中再点一次，当前动画会跳成默认的淡化；
- 过渡被跳过时，没有退回原来的淡入效果；
- 旧版 Safari（低于 16.4）上的悬停样式写法兼容性；
- 等待时的光标样式规则范围过大；
- 一处代码注释表述不准确；
- 旧提示词链接的重定向没有被解析。

## 已知限制

- **iOS Safari**：需要 18 及以上才支持同文档 View Transitions，旧版本照常跳转、不放动画。安卓微信内置浏览器的支持情况要在真机上确认。
- **系统级“减少动态”**：gstack 不能模拟系统设置，这次只模拟了网站内部的判断路径。真机上开启“减少动态”后，需要再确认一遍。
- **无头浏览器的局限**：帧率和手感无法验证，要在真机上体验。
