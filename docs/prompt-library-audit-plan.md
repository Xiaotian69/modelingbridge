## 3. 既有 9 条模板逐条审查

整体结论：适合作为学习引导的初版，输入、前提、限制和来源元信息较完整，但内容较短、证据要求不一致，尚不足以作为全面的赛后检查工具。9 条均为 self-checked，界面正确显示“待复核”，不应由 AI 自行改成负责人已审核。

| 模板 | 已有价值 | 建议改进 |
| --- | --- | --- |
| 赛题拆解 · 基础版 | 要求学生先写理解，回到题面寻找条件 | 区分题面事实、推断与待确认信息，附原句证据，避免把隐含要求当事实 |
| 小问输入输出表 | 明确输入、输出、依赖与评价标准 | 不足信息写待补充；保留原拆分同时给出可核对的修订建议 |
| 假设与变量自检 | 审查合理性、单位和符号 | 补变量取值域、假设依据、失效条件、检验所需数据 |
| 模型选择对比 | 比较适用条件并加入简单基线 | 增加样本规模、数据泄漏、计算预算、评价指标与验证划分；不按模型复杂度推荐 |
| 数据清洗计划审查 | 已关注信息损失和训练测试泄漏 | 明确先划分再拟合预处理；保留原数据及变更记录，区分测量错误与真实极值 |
| 代码报错排查 | 完整报错、最小改动、不重写程序 | 明确 Python / MATLAB 环境、依赖、输入形状、预期/实际输出及回归验证；禁止声称未执行代码已运行 |
| 图表方案评审 | 强调图与结论对应 | 补单位、样本量、不确定性、坐标截断、可读性及原始结果可追溯性 |
| 论文自检清单 | 实际是摘要检查，最新提交已移除依赖未见正文的判断 | 更名为摘要草稿自检；加入“材料不足，无法判断”，不把摘要检查冒充全文审查 |
| AI 使用记录整理 | 如实披露，不淡化 AI 作用 | 未提供的版本、时间、独立完成工作和人工核验必须标待补充，不自行生成事实 |

共性问题：COMMON_LIMITS 和官方规则提醒目前只显示在页面，不会随 templateText 被复制。外部 AI 收到的文本因而缺少部分关键边界，需要统一生成完整可复制文本。

## 4. 交互问题与证据

1. **示例覆盖已有输入**：fillExamples 重建整个 values 对象。真实浏览器输入“我的测试代码”后点击“填入示例”，内容被示例替换。建议改成仅补空项，保留用户内容和来源标记。
2. **可选项仍作为未完成占位符**：填充函数不区分 required。建议可选空值生成明确的“未提供”，必填缺失保留占位符并点名提醒，继续保留复制后在外部补充的现有约定。
3. **缓存结构校验不足**：readPromptVars 只检查 values 是对象，字段可能是数字，后续 trim 会抛错；examples/prefilled 也未校验数组。需兼容合法旧缓存，丢弃非法字段。
4. **跨案例旧题面风险**：预填只在字段为空时写入，无法区分未改动的旧自动预填和用户输入。仅对仍标记为自动预填的字段更新当前题面，不覆盖手工改过的内容。
5. **空结果清除回程参数**：查看全部使用 setParams({})，会丢失 back。只清除筛选参数，保留已校验的站内回程。
6. **筛选语义与复制提示**：增加比赛维度、匹配数量和准确的空状态；原文复制、已填文本复制、缺少必填项、仍用示例需明确区分。

第 1 项已用真实浏览器复现；其余为代码检查发现，实施时补针对性的行为测试。不将它们表述为已经修复。

## 5. 本地参考资料初审

对用户指定的 4 份 DOCX 和提示词目录下 DOCX 进行了文本提取与初筛：共 22 份，按正文文本去重为 16 份。重点查看了模型适配、AI 痕迹、自查红线、论文检查与获奖预测四类内容。目录中的 PDF 和视频仅盘点，未完成内容审阅；本轮不依赖它们编写或导入模板。没有将原文或原文件写入公开仓库，也未向外部服务上传。

可作为原创模板的需求参考：模型与小问适配、假设依据、结果与图表一致性、论文逻辑、引用证据、AI 使用记录。新模板从任务目标和输入输出重新编写，不拼接原文或仅替换措辞。

不直接采用的内容：材料中自称官方的固定评分权重、固定字数页数、评委偏好、获奖等级预测、仅凭文风给出的 AI 生成百分比，以及无需人工判断的全自动合规判定。它们在所读材料中缺少可核验依据；本审计不据此判定真实官方规则。论文格式与 AI 使用规则由使用者提供当年官方文件及出处，无材料时输出“待核实”。

模板输出建议采用“问题位置 / 已提供证据 / 判断或无法判断 / 修改建议 / 人工核验步骤”，不承诺奖项，不把语言风格视为 AI 使用证明。

## 6. 推荐实施方案

三种路径：仅补内容工作量小，但无法满足筛选和交互需求；整体重建会扩大风险并重复现有能力；**推荐原模块渐进增强**，保留 URL、既有 ID、主题与七关入口。

### 内容范围

首轮目标 15 条：逐条修订现有 9 条，新增 6 条：异常值分析、敏感性分析、求解结果核验、摘要信息组织与写作指导、论文全文逻辑与格式检查、按官方材料核对 AI 使用记录。代码排错模板同时支持 Python 与 MATLAB，不为同一流程堆积近似模板。

每条固定包含用途、使用前提、必填/可选变量、可替换示例、输出结构、证据不足时的处理、使用限制、适用关卡/比赛标签、来源、版本及复核状态。摘要指导以学生已完成的真实结果和草稿为输入，不虚构结果或生成一键提交终稿。

比赛标签允许通用、国赛 CUMCM、美赛 MCM/ICM、校赛/训练，表示使用语境，不代表官方允许使用 AI。通用项随任一比赛显示；比赛专项条目只有具备实际语境差异时才打标签。比赛规则全部注明以当年官方要求为准，不内置未经核验的条款。

### 交互与数据流

保留桌面筛选/列表/详情和手机列表/详情切换；增加原生比赛下拉，筛选组合写入 URL，搜索匹配标题、用途和标签。继续使用原主题 token、按钮、表单和间距，新增样式只作用于提示词页面。

类型与内容仍从 content/prompts 导出同一公共接口，可在目录内拆分内容与纯函数以降低维护成本。变量填写 → 校验必填/可选及示例来源 → 生成纯文本与预览 → 同一生成函数供详情复制和原文复制使用。使用限制应进入最终文本；文本不作为 HTML 执行。

会话保存保持本标签页范围；修复缓存结构异常和跨案例自动预填，不自动带入学生作答。复制失败显示可选中文本框，成功及缺失字段反馈使用 aria-live。保留草稿不公开、待复核不冒充已审核。

### 文件边界

预计修改：content/prompts/index.ts、prompts.test.ts、pages/Prompts.tsx、Prompts.test.tsx、pages/library/PromptDetail.tsx。按需要在这两个模块目录新增类型/数据/填充/存储测试与局部 CSS。copyText.ts 仅在确有需要时改动。

七关使用现有按 stage 查询的入口，原则上不改 Quest.tsx，仅补 QuestFlow.test.tsx 的入口和预填回归用例。优先把预填修复限制在 PromptDetail.tsx 内。全局 CSS、App 路由、首页、动画、教材、判分、账号、后端及部署均不在实施范围。

### 验证与交付

先补关键失败路径和内容契约测试，再实现。验证 15 条模板变量完整对应、标签合法、七关覆盖、组合筛选、空结果回程、变量实时更新、缓存异常、示例保护、跨案例预填、复制三种结果。运行独立 TypeScript、全量测试和构建。

使用 gstack 真实浏览器检查桌面和手机、浅深主题、筛选组合、直接链接、长文本、变量、复制失败与成功、七关往返。若当前浏览器拒绝真实剪贴板权限，区分真实失败检查与受控成功测试，不宣称已经完成真实系统剪贴板验收。

完成后在本分支提交，提供文件清单、测试证据、截图与未完成事项，等待用户验收；不自动创建 PR、推送或合并。
