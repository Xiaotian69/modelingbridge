# 赛事日历维护手册

数据在 `frontend/src/content/contests/`，页面代码一般不需要改。**系统不会自动抓取或核验通知**，以下都是人工流程。

## 文件结构

| 文件 | 内容 | 多久改一次 |
|---|---|---|
| `catalog.ts` | 赛事档案：名称、主办、官网、类别、适合人群 | 新增或下线赛事时 |
| `editions/YYYY.ts` | 某一年各赛事的届次数据：状态、事件、来源 | 每次官方发布通知时 |
| `index.ts` | 解析、推算、状态和导出逻辑；`ALL_EDITIONS` 与 `CALENDAR_YEARS` | 新增年份时改两行 |
| `contests.test.ts` | 数据规则检查 | 一般不用改 |

## 每年的工作

1. **新增年份**（例如 2028）：复制 `editions/2027.ts` 为 `editions/2028.ts` 并清空数组，然后在 `index.ts` 中：
   - 把它加入 `ALL_EDITIONS`；
   - 把 `CALENDAR_YEARS` 改为 `[2026, 2027, 2028]`（建议保留去年、今年、明年三个年份）。
   数组为空时，页面会自动按上一年的官方日期推算并标为“预计”。
2. **官方发布通知后**，在对应年份文件中增加一条，就会覆盖推算值：

```ts
{
  contestId: "cumcm",              // 必须是 catalog.ts 中已有的 id
  year: 2027,
  title: "第三十六届",             // 可选
  status: "scheduled",             // scheduled / suspended / cancelled / postponed
  events: [
    { kind: "registration", end: "2027-09-06T20:00", label: "向全国组委会报名截止", certainty: "official", note: "学校截止更早" },
    { kind: "contest", start: "2027-09-09T18:00", end: "2027-09-12T20:00", certainty: "official" },
  ],
  sources: [
    { title: "2027 高教社杯……第一次通知", url: "https://www.mcm.edu.cn/…", publisher: "中国工业与应用数学学会", type: "organizer", checkedAt: "2027-03-30" },
  ],
}
```

3. 运行 `npm test`，`contests.test.ts` 会检查：来源 URL 和核验日期齐全、结束时间不早于开始时间、比赛日期落在所属年份、报名截止不晚于比赛开始、同一赛事一年只有一条。
4. 提交时在说明中写明来源和核验日期，由另一人打开链接复核后再合并。

## 写法约定

- **时间按官方原文所在时区记录，不要自己换算。** 北京时间省略 `tz`；美国东部时间写 `tz: "America/New_York"`，程序按美国夏令时规则自动区分 EST / EDT（例如 1 月比赛为 EST，5 月成绩公布为 EDT），不要手写固定偏移。页面会自动换算为北京时间，并同时显示官方原文时间。
- 只写到日期：`"2026-11-25"`；只写到月份：`"2026-08"`；原文写“24 时”：`"2026-04-30T24:00"`。
- 原文写“即日起至……”时，可以用通知落款日作为 `start`，并在 `note` 中说明；落款日不明时省略 `start`，页面会显示为“报名截止前”。
- 报名、比赛、提交、成绩是**不同的事件**，不要合并成一条；分阶段的比赛用 `kind: "stage"` 加 `label`（如“复赛”“第二阶段”）。
- `certainty`：
  - `official`：主办方原文，或主办方指定的官方报名平台，或注明原发布方的转载、且内容与原文一致；
  - `unverified`：只看到检索摘要或二手信息，没有打开原文核对。会显示虚线框，并且不导出到日历。
  - “预计”由程序推算，**不要手写**。推算规则：以最近一届举办过的官方数据为基础，比赛开始日对齐到相同的星期几（多数赛事固定在周四、周五开赛），其余节点与比赛保持相同的间隔；固定在节假日的赛事在 `catalog.ts` 中写 `predictAnchor: "date"`（目前是五一赛、华东杯），保持相同的月日。推算的届次不带往届备注，所有时间前面都加“约”。
- 来源 `type`：`organizer`（主办方）、`platform`（官方报名平台）、`repost`（转载，`publisher` 中写明原发布方）。转载只作为临时来源，找到主办方原文后替换。
- 知道有这个节点但没能核实日期（例如报名截止、第一阶段）：写进 `pending: [{ kind, label?, note }]`。页面会显示“待核实”，不会画在时间轴上，也不会进入倒计时或导出。
- 原文自相矛盾或疑似笔误的字段不要收录，写进 `notes`。

## 特殊情况

| 情况 | 处理 |
|---|---|
| 暂停 / 取消 | `status: "suspended"` 或 `"cancelled"`，`events: []`，在 `notes` 中写明公告日期和原因，来源附公告。暂停或取消的届次不会被用来推算下一年 |
| 延期 | 改为新的日期，`status: "postponed"`，在 `notes` 中写明原日期和延期公告 |
| 一年两届（春季 / 秋季） | 在 `catalog.ts` 中作为两项赛事（如 `shuwei-spring`、`shuwei-autumn`） |
| 主赛与分赛项 | 同上（如 `apmcm` 与 `apmcm-cn`），规则不要混用 |
| 停办 | 从 `catalog.ts` 删除前，先确认没有年份文件引用它 |

## 以后可以做的自动化（尚未实现）

- 定期用脚本抓取各主办方的通知列表页，只**提醒**维护者“有新通知”，由人工核对后填写。不建议自动写入日期，因为不少通知是图片或 PDF 扫描件，自动识别容易出错。
- 在 CI 中检查来源链接是否仍然有效（只告警）。
