## 5. 各节教学目标

1. 区分课本习题与现实问题；知道模型是可计算、可检验的简化描述，模型 ≠ 现实（地铁线路图类比）；纠正“建模就是套公式”。
2. 理解假设为何必要、好的假设的三个特点；分清观测数据、假设、设定数据；理解结论随假设变化。
3. 走一遍完整流程，每步回答“为什么做 / 需要什么 / 卡在哪 / 结果 / 下一步怎么用”；亲眼看到“平均值方案 10 天迟到 3 天 → 回到目标 → 用最长用时 7:45 → 10 天都准时，但只对已有记录成立”。
4. 三类工作各做什么、不只是什么；每项任务都需要多类同学；分歧处理、时间安排与休息。
5. 比赛的一般过程；规则因赛事和年份而异，以当届官方为准；比赛价值不只是获奖；诚信与 AI 使用。
6. 先识别问题类型再学方法；四类问题与模桥课程的对应；没有万能算法。
7. 亲手完成一次简化建模：目标 → 现状 → 变量与假设 → 求解 → 检验 → 小结。
8. 把刚才的操作映射回九步流程；理解“在这些条件下最好的安排”。
9. 自主选择下一条路线；可以跳过第零课。

## 6. 互动案例：共享雨伞

**设定**（教学数据）：A 点（教学楼）现有 20 把、预计 40 人借；B 点（宿舍区）现有 40 把、预计 20 人借；共 60 把；每人借 1 把；下雨前调一次，不计搬运成本，雨中不归还，学生只在本点借。

**决策变量** x = 从 B 调到 A 的伞数，允许范围 −20 ≤ x ≤ 40（不能调走比现有更多的伞；负数表示 A→B），整数。

**目标** 借不到伞的人数 S(x) = max(40 − (20 + x), 0) + max(20 − (40 − x), 0)，越小越好。

**玩法**：① 在三个候选指标中选出能衡量“借不到伞”的数（其他两个不判错，给出计算后的说明：平分 30/30 时 A 仍缺 10；不调配时 A 缺 20，“少调动”只适合作次要目标）→ ② 计算不调配时的缺口（输入 20；对 0、40、负数给出各自的错因）→ ③ 选出决策变量，阅读四条假设及“不成立时会怎样”，看到关系式 → ④ 滑块 / ±按钮 / 精确输入调整 x，两点的伞数、需求、借到人数、缺口实时变化；非法输入（41、−21、2.5）被拒绝并说明原因；“把每一种调法都算一遍”画出 61 种方案的缺口曲线；确认最优方案后才能进入下一步（卡住可一键设为最优）→ ⑤ 改变需求（四个情景 + 两个自由滑块 0–70），对比“你的方案”与“新的最优”，自动说明多个最优、需求超过总数等情况 → ⑥ 小结，并在本机记录“雨伞案例完成”。任何一步可退回，标题栏可重新开始。

**数学验证**：`verify_intro.py` 用 `scipy.optimize.linprog`（HiGHS）把问题写成线性规划，求最小缺口及最优调配区间，写入 `intro-verified.json`；`math.test.ts` 逐点核对 61 个方案的缺口曲线、4 个情景和 15×15 = 225 个需求组合的最优值与区间，并与闭式解 max(dA + dB − 60, 0) 交叉检查。浏览器实测：默认 x = 20 唯一最优（缺口 0）；A 点多 10 人 → 最小缺口 10，x ∈ [20, 30]；雨小 → x ∈ [10, 25]；宿舍区有活动 → 原方案缺 15，新最优 x = 5；A 5 / B 50 → 最优为从 A 调 10 把到 B。

**出门时刻计算器**（第 3 节）：10 天用时 11、12、10、13、11、12、15、11、12、13 分钟（第 7 天雨），平均 12，最长 15，晴天最长 13；7:40–7:52 每个出门时刻的准时天数与迟到天编号都与 numpy 结果一致。

### 6.1 调配动画与插图位置（10-17 追加）

- **雨伞场景**（`UmbrellaScene.tsx`）：一伞一图标；需求画成虚线方框，没借到伞的人是橙色虚线框，多余的伞为灰色。改变 x 时恰好 |Δx| 把伞移动，其余不动。出现在第 2、4、5 步。测试验证：每个 x 下两点图标数 = 伞数、橙框数 = 缺口、移动的图标数 = |Δx|。浏览器实测：x 从 0 拖到 20，第 25 号伞在 350 ms 时位于途中（474 → 219 → 166），动画真实发生。
- **减少动态效果**：细雨在 `prefers-reduced-motion: reduce` 下不显示（构建产物中的规则已核对）；调配时长和先后间隔都乘以 `--motion-scale`，该设置下为 0，实测变为瞬间完成。场景为装饰（`aria-hidden`），数字仍以文字给出。
- **六个插图位置**：封面、第 1 节两处、第 3、4、9 节开头；把图片按约定文件名放进 `frontend/src/learning/intro/img/` 即自动显示，缺的不显示。提示词与规格见 `docs/design/intro-illustrations.md`。**已接入负责人选定的极简版 V2 六张插图**（WebP，共约 234 KB，懒加载，2:1 显示）；逐张检查无文字、数字和标识，替代文字按实际画面编写；桌面、手机、深色主题实测显示正常。

## 7. 理解检查（6 题，单选，可跳过，不计成绩）

| 题 | 检验什么 | 选项层面 |
|---|---|---|
| 1 | 区分现实问题与模型 | 关于同一问题的四句话：问题 / 模型 / 数据 / 目标 |
| 2 | 区分假设与数据 | 四句关于通勤的陈述，三句可测量、一句是推断 |
| 3 | 结果为什么要检验 | 对同一检验结果的四种做法：重算 / 回到目标 / 删数据 / 怪运气 |
| 4 | 建模、编程、写作的关系 | 对同一个错误数字的四种责任看法 |
| 5 | 按问题选思路 | 四类问题 |
| 6 | 识别优化目标（迁移到新情境：志愿者分到食堂） | 模型的四要素：目标 / 约束 / 决策变量 / 数据 |

每个错误选项都有单独的错因说明（例如“这是一条数据”“把目标问题当成计算错误”“删改了不合心意的数据”），提示与解析按需展开；结果写入现有学习记录（`checkpoints`），在学习记录与课末完成卡中显示“尝试过 x/6”。
